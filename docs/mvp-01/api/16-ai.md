# Inteligência artificial (`ai`)

> Parte de [api.md §4](../api.md#4-especificação-por-endpoint). Convenções e erros genéricos: api.md §1–§2. Decisões: DEC-037 e DEC-079; provedor em ADR-013 (pendente — PEND-21).

| ID | Método | Rota | Permissão | Story |
|---|---|---|---|---|
| AI-01 | POST | `/processes/{id}/ai-generations` | `AI_GENERATE` + POL-18 | US-115, US-117..US-121 |
| AI-02 | GET | `/ai-generations/{generationId}` | `PROCESS_VIEW` | US-115 |
| AI-03 | GET | `/processes/{id}/ai-generations` | `PROCESS_VIEW` | US-115 |
| AI-04 | POST | `/ai-generations/{generationId}/discard` | solicitante (RN-AI-13) | US-115, US-117 |
| AI-05 | GET | `/ai/availability` | impl. | US-116 |
| AI-06 | GET | `/ai/usage` | `SETTINGS_MANAGE` | US-116 |

Fluxo: o cliente pede a geração (AI-01, **202**). O worker da fila `ai-generation` chama o provedor fora de transação. O cliente consulta AI-02 até um estado final: a cada 2 s, recuando até 5 s; após 3 min passa a depender da notificação `AI_GENERATION_READY`/`AI_GENERATION_FAILED`.

A **aplicação** e a **revisão** são comandos dos módulos donos e ficam nos arquivos deles:
- [03-documents.md](03-documents.md): DOC-26 (aplicar seções) e DOC-27 (revisar seções);
- [08-risks.md](08-risks.md): RSK-11 (aplicar riscos) e RSK-12 (revisar riscos).

Representação `AiGeneration` (AI-02):
```ts
{
  id: string; processId: string; documentId: string | null;
  targetModule: 'DFD' | 'ETP' | 'RISK_MAP' | 'TERM_OF_REFERENCE';
  kind: 'DRAFT' | 'SECTION'; action: 'REWRITE' | 'COMPLETE' | 'SUMMARIZE' | null;
  sectionKey: string | null; baseRevision: number | null;
  status: 'QUEUED' | 'RUNNING' | 'SUCCEEDED' | 'FAILED' | 'CANCELED' | 'APPLIED' | 'DISCARDED' | 'EXPIRED';
  requestedBy: { id: string; name: string };
  createdAt: string; startedAt: string | null; completedAt: string | null; expiresAt: string | null;
  provider: string; model: string | null; promptKey: string; promptVersion: string;
  usage: { inputTokens: number | null; outputTokens: number | null; totalTokens: number | null };
  placeholdersCount: number; groundingReplacements: number;
  inputRefs: AiInputRef[];                 // entities.md §5.10 — sem conteúdo
  output: AiGenerationOutput | null;       // entities.md §5.10 — só para quem vê o processo; null fora de SUCCEEDED/APPLIED
  errorCode: string | null;                // PROVIDER_UNAVAILABLE | PROVIDER_RATE_LIMITED | TIMEOUT | CONTENT_FILTERED | CONTEXT_TOO_LARGE | OUTPUT_INVALID | CANCELED_BY_POLICY
  appliedAt: string | null; appliedTargets: { sectionKeys: string[]; riskIds: string[] } | null;
}
```
O custo (`costUsd`) não aparece em AI-02/AI-03; só em AI-06.

### AI-01 — Solicitar geração com IA
`POST /api/v1/processes/{id}/ai-generations` · **Permissão:** `AI_GENERATE` + POL-18 · **Story:** US-115 (contrato e pipeline); US-117, US-118, US-119, US-120 (rascunhos); US-121 (ajuste de seção)

- **Cabeçalhos:** `Idempotency-Key` obrigatório · limite próprio de 10 req/min por usuário + tenant (api.md §1.6)
- **Parâmetros:** `id` (path, uuid, obrigatório) — processo
- **Request:**
```ts
{
  targetModule: 'DFD' | 'ETP' | 'RISK_MAP' | 'TERM_OF_REFERENCE';
  documentId?: string;          // obrigatório, exceto RISK_MAP sem documento emitido
  kind: 'DRAFT' | 'SECTION';
  action?: 'REWRITE' | 'COMPLETE' | 'SUMMARIZE';   // obrigatório se SECTION
  sectionKey?: string;          // obrigatório se SECTION
  needSummary?: string;         // obrigatório no DRAFT do DFD; opcional nos demais; quando informado, 20..2.000
  instruction?: string;         // ≤ 500; opcional
}
```
- **Response:** `202 { data: AiGeneration /* status QUEUED */, meta: { pollAfterMs: 2000 } }` + `Location: /api/v1/ai-generations/{generationId}`
- **Erros:**

| HTTP | `code` | Quando |
|---|---|---|
| 403 | `PERMISSION_DENIED` | Sem `AI_GENERATE` no escopo do processo ou sem permissão de edição do tipo alvo |
| 403 | `AI_DISABLED` | `ai.enabled = false` no órgão |
| 403 | `NOT_PROCESS_CUSTODIAN` | POL-02 sem custódia nem participação |
| 404 | `NOT_FOUND` | Processo ou documento inexistente, de outro tenant ou não visível |
| 409 | `DOCUMENT_NOT_EDITABLE` | Documento alvo fora de `DRAFT`/`RETURNED` |
| 409 | `AI_GENERATION_IN_PROGRESS` | Já há geração ativa para o alvo (`meta.generationId`) — RN-AI-12 |
| 409 | `IDEMPOTENCY_IN_PROGRESS` | Requisição idêntica em processamento |
| 422 | `VALIDATION_ERROR` | Corpo inválido; `needSummary` fora do limite (`TOO_SHORT`/`TOO_LONG`) ou ausente no DFD (`REQUIRED`); `action`/`sectionKey` ausentes em `SECTION` (`CONDITIONAL_REQUIRED`); `documentId` de outro processo (`REFERENCE_NOT_FOUND`) |
| 422 | `AI_PREREQUISITE_MISSING` | Antecessor da cadeia ausente (`meta.missing[]`: `DFD` para ETP e mapa de riscos; `ETP` para TR) |
| 422 | `AI_SECTION_EMPTY` | `REWRITE`/`SUMMARIZE` em seção com menos de 50 caracteres |
| 422 | `AI_SECTION_NOT_SUPPORTED` | `sectionKey` fora do template ou sem narrativa |
| 422 | `AI_USAGE_LIMIT_REACHED` | Limite mensal do órgão (RN-AI-18) |
| 422 | `AI_USER_DAILY_LIMIT_REACHED` | Limite diário do usuário (RN-AI-19) |
| 422 | `DOCUMENT_TYPE_NOT_ALLOWED_IN_STAGE` | Tipo do documento não permitido na etapa atual (POL-02) |
| 422 | `IDEMPOTENCY_KEY_REUSED` | Mesma chave, corpo diferente |
| 429 | `RATE_LIMITED` | Acima de 10 req/min |
| 503 | `AI_PROVIDER_UNAVAILABLE` | `AI_PROVIDER=none` ou circuito aberto (`Retry-After`) |

- **Efeitos:** grava `AiGeneration` (`QUEUED`, `reservedTokens`, `provider`, `promptKey`/`promptVersion`). Pedido de `DRAFT` com proposta `SUCCEEDED` anterior não aplicada do mesmo usuário → a anterior vira `DISCARDED` (RN-AI-32). Auditoria `ai.generation_request` (`DATA_CHANGE`). Evento `AiGenerationRequested` (`ai.generation_requested`). Após o commit, job na fila `ai-generation` (`jobId = generationId`).
- **Efeitos do término (worker):**
  - Sucesso: `SUCCEEDED`, com `output`, `inputRefs`, `contextHash`, `outputHash`, tokens, `costUsd` e `expiresAt`; auditoria `ai.generation_complete` (`SYSTEM`); evento `AiGenerationCompleted` → timeline `AI_CONTENT_GENERATED` e notificação `AI_GENERATION_READY`.
  - Falha: `FAILED` com `errorCode`; auditoria `ai.generation_fail`; evento `AiGenerationFailed` → notificação `AI_GENERATION_FAILED`.
  - Ao cruzar 80% ou 100% do limite mensal: `AiUsageThresholdReached`.
- **Notas:** POL-18 e os pré-requisitos da cadeia são revalidados no worker antes de chamar o provedor; se falharem (IA desligada, permissão, limites, antecessor cancelado), a geração vira `CANCELED` com `CANCELED_BY_POLICY` e a reserva é liberada. A lista de entradas e avisos exibida antes do pedido é montada pelo cliente com os dados já carregados (DFD-01, ETP-05, PRS-01, RSK-01); os avisos definitivos vêm em `output.warnings`. Logs e eventos nunca levam `needSummary`, `instruction`, contexto ou saída (DEC-138).

### AI-02 — Consultar geração
`GET /api/v1/ai-generations/{generationId}` · **Permissão:** `PROCESS_VIEW` do processo da geração · **Story:** US-115

- **Cabeçalhos:** —
- **Parâmetros:** `generationId` (path, uuid, obrigatório)
- **Request:** —
- **Response:** `200 { data: AiGeneration }`, com `ETag` = status + `updatedAt`, para consulta condicional (`If-None-Match` → 304).
- **Erros:**

| HTTP | `code` | Quando |
|---|---|---|
| 403 | `PERMISSION_DENIED` | Sem `PROCESS_VIEW` do processo |
| 404 | `AI_GENERATION_NOT_FOUND` | Inexistente ou de outro tenant |

- **Efeitos:** nenhum (leitura).
- **Notas:** `output` só vem preenchido em `SUCCEEDED` e `APPLIED`. Em `EXPIRED`, `DISCARDED` e `CANCELED`, a proposta permanece em `AI-03`/auditoria apenas como metadados.

### AI-03 — Listar gerações do processo
`GET /api/v1/processes/{id}/ai-generations` · **Permissão:** `PROCESS_VIEW` · **Story:** US-115

- **Cabeçalhos:** —
- **Parâmetros:** `id` (path, uuid) · `documentId?` · `targetModule?` · `kind?` · `status?` (lista) · `requestedById?` · paginação por cursor (api.md §1.2), ordem `createdAt desc`
- **Request:** —
- **Response:** `200 { data: AiGeneration[] /* sem output */, meta: { nextCursor } }`
- **Erros:** 403 `PERMISSION_DENIED` · 404 `NOT_FOUND` (processo) · 422 `VALIDATION_ERROR` (filtro inválido)
- **Efeitos:** nenhum.
- **Notas:** alimenta a aba "Histórico de IA" do painel SCR-117 (quem, quando, tipo, modelo, versão do prompt, tokens, status).

### AI-04 — Descartar proposta ou cancelar geração
`POST /api/v1/ai-generations/{generationId}/discard` · **Permissão:** solicitante da geração (RN-AI-13) · **Story:** US-115, US-117

- **Cabeçalhos:** —
- **Parâmetros:** `generationId` (path, uuid)
- **Request:** `{}`
- **Response:** `200 { data: AiGeneration }`. `SUCCEEDED` vira `DISCARDED`; `QUEUED`/`RUNNING` vira `CANCELED`. Estados finais são devolvidos sem mudança (idempotente).
- **Erros:**

| HTTP | `code` | Quando |
|---|---|---|
| 403 | `AI_GENERATION_NOT_OWNED` | Usuário não é o solicitante |
| 404 | `AI_GENERATION_NOT_FOUND` | Inexistente ou de outro tenant |
| 409 | `AI_GENERATION_NOT_APPLICABLE` | Já `APPLIED` |

- **Efeitos:** auditoria `ai.generation_discard` (`DATA_CHANGE`). Em `RUNNING`, o worker descarta a resposta do provedor ao terminar; os tokens consumidos contam no uso.

### AI-05 — Disponibilidade da IA para o usuário
`GET /api/v1/ai/availability?processId=&documentId=` · **Permissão:** implícita (vínculo ativo) · **Story:** US-116

- **Parâmetros:** `processId?`, `documentId?` (query, uuid). Sem eles, responde só sobre o órgão e o usuário.
- **Response:**
```ts
200 { data: {
  enabled: boolean; providerAvailable: boolean; canGenerate: boolean;
  reasons: Array<'AI_DISABLED' | 'AI_PROVIDER_UNAVAILABLE' | 'AI_USAGE_LIMIT_REACHED' | 'AI_USER_DAILY_LIMIT_REACHED' | 'PERMISSION_DENIED' | 'DOCUMENT_NOT_EDITABLE'>;
  monthly: { percentUsed: number; usedTokens?: number; limitTokens?: number };   // absolutos só com SETTINGS_MANAGE
  userDaily: { used: number; limit: number };
} }
```
- **Erros:** 404 `NOT_FOUND` (processo/documento de outro tenant ou não visível).
- **Notas:** o editor usa a resposta para mostrar, ocultar ou desabilitar com explicação as ações de IA (screens.md §1.4). Cache curto no cliente (30 s), invalidado após AI-01.

### AI-06 — Consumo de IA do órgão
`GET /api/v1/ai/usage?month=YYYY-MM` · **Permissão:** `SETTINGS_MANAGE` · **Story:** US-116

- **Parâmetros:** `month` (query, `YYYY-MM`, padrão: mês corrente no fuso do tenant)
- **Response:**
```ts
200 { data: {
  month: string; limitTokens: number; usedTokens: number; reservedTokens: number; costUsd: string | null;
  generations: { total: number; byStatus: Record<AiGenerationStatus, number> };
  byDocumentType: Array<{ targetModule: string; generations: number; totalTokens: number; costUsd: string | null }>;
  byKind: Array<{ kind: 'DRAFT' | 'SECTION'; action: string | null; generations: number; totalTokens: number }>;
  byUser: Array<{ userId: string; name: string; generations: number; totalTokens: number }>;
} }
```
- **Erros:** 403 `PERMISSION_DENIED` / `MFA_REQUIRED` (POL-14) · 422 `VALIDATION_ERROR` (`month` inválido ou futuro)
- **Notas:** `costUsd` é decimal em string (DEC-003), calculado pela tabela de preços da plataforma; `null` quando algum modelo do mês não tem preço cadastrado. A consulta não é auditada (leitura administrativa).
